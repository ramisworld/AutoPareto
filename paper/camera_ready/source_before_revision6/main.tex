\begin{abstract}
Autonomous research agents write code, run machine-learning experiments and choose the next experiment from the results. What they discover depends on how they are scored. We built AutoPareto to study this dependence. A coding agent edits a small Transformer language model's training script, a protected harness trains each version for 300 seconds on one GPU, and the agent is scored on prediction quality, generation speed and memory. Under a time budget, a faster program also trains on more data. Agents from two model families found this lever on their own, shrinking the batch and the number of layers so that more optimizer updates and more data fit into the budget. Claude Opus 5.5 then rewrote the generation code to use CUDA-graph replay and kernel fusion, known techniques that cut the overhead of launching small GPU operations per token. Its scored decoding ran about 31 times faster than the starting model, yet a full generation was only 5.3 times faster, because the agent recorded the graph in the untimed prompt step. In pre-registered retraining on fresh seeds, a recipe that trained 1.8 times faster than a quality-only agent's best recipe could not be distinguished from it at equal time but was worse at all three equal-token budgets. Opus's recipes, tested at the largest budget, were worse still. The agents found real efficiency, not models that learn more from each token. Where architecture search asks which model is best, AutoPareto asks what the scoring rules rewarded.
\end{abstract}

\noindent\textbf{Keywords:} autonomous ML research; neural architecture search; Transformer efficiency; multi-objective optimization; reproducibility

\section{Autonomous research result}\label{partone}

\subsection{The question}\label{sec:question}
An autonomous ML research agent edits code, runs an experiment and uses the result to choose its next edit. Karpathy's autoresearch \citep{autoresearch} gives every candidate training script the same 300 seconds on one GPU and scores the resulting model, so a program that runs faster also trains on more data. \textbf{We ask whether agents under such a budget find models that learn better or models that train faster, and whether their gains survive once this coupling is removed.}

\textbf{Terms.} Quality is measured in \emph{bits per byte} (BPB), the average number of bits the model needs to encode each byte of unseen text, so lower is better. Agents saw \emph{validation BPB}. We confirm results on \emph{held-out BPB}, computed on a pinned shard that no agent saw. A model trains on \emph{tokens}, pieces of text, and changes its weights once per batch in an \emph{optimizer update}, so halving the batch doubles the updates for the same tokens. A model's \emph{exposure} is the number of tokens it trained on.

\needspace{3\baselineskip}\textbf{Two training contracts.} A \emph{fixed-time contract} gives every candidate 300\,s of training, so faster code processes more tokens and makes more updates. A \emph{fixed-token contract} gives every candidate the same number of tokens, however long training takes. Appendix~\ref{app:glossary} is a glossary.

\subsection{How AutoPareto works}\label{sec:brief}
\textbf{The human sets the rules.} The task is to train a small decoder-only Transformer language model on web text (ClimbMix) for 300\,s on one NVIDIA A40, starting from a model with 8 layers, width 512 and 50.3M parameters. Candidates are scored on validation BPB, on \emph{decode throughput} (tokens per second when generating one token at a time) and on peak generation memory. The agent may edit only \texttt{train.py}, which holds the model, optimizer, training loop and, later, the inference code. A protected controller does all training and measurement.

\textbf{The agent runs the loop} (Figure~\ref{fig:loop}). In each \emph{attempt} the agent reads the hypotheses, code changes and measurements of all earlier attempts, picks a \emph{parent} recipe, writes down a hypothesis and the trade-off it expects, and only then edits \texttt{train.py}. The controller checks that nothing else changed, then trains, measures and records the result, failures included. Any eligible earlier recipe can be a parent, so the search is a tree, not a chain. A recipe is on the \emph{Pareto frontier} if no other recipe is at least as good on all three objectives and better on one. Historical parents had to be on the frontier, while Pair-A parents only had to pass the quality checks.

\textbf{What we ran.} In the \emph{historical campaigns} (July and August 2026), \texttt{gpt-5.6-sol} working through Codex ran three 25-attempt AutoPareto campaigns on seeds 0, 1 and 42. Their best-quality recipe is \emph{AP-Q} (4 layers, 29.4M parameters). A quality-only AutoResearch campaign produced \emph{AR-ref} (8 layers, 50.3M), and five classical optimizers searched the same task. In \emph{Pair-A} (September to November), a frozen harness that also lets the agent rewrite inference code, Codex ran \CRCxAttempts{} attempts and Claude Opus 5.5 ran \CROpAttempts{} (\CROpValid{} valid) from the same starting model, seed and prompts. Opus's best recipe came within its first 25 (\S\ref{sec:interventions}). We rank neither agents nor search methods \citep[cf.][]{ferreira}.

\textbf{Train more in 300\,s (Figure~\ref{fig:opus}, milestones 1 to 4).} We quote the hypothesis Opus recorded before each attempt. The first reads ``The model is therefore optimizer-update-limited, not token-limited.'' Halving the batch (A1) raised the updates from 163 to \CRThreeOneUpd{}, and validation BPB fell from 1.200 to 1.179. Cutting the model from 8 to 3 layers (A3 to A5) left \CRThreeFiveParams M parameters, so \CRThreeFiveTok M tokens fit into 300\,s instead of \CRThreeOneTok M. At 2 layers the loss of capacity won: Opus recorded that ``the quality prediction was falsified'' (A6), went back to the 3-layer parent and halved the batch again (A7: \CRThreeSevenUpd{} updates, BPB \CROpBestSeven). A third halving cost tokens and quality (A12).

\textbf{Make decoding faster (milestones 5 and 6).} After A7 validation BPB barely moved: \CRThreeLateValid{} more valid attempts improved it by \CRThreeLateGain{} in total. Opus turned to the decode path and labelled \CROpLateInf{} of these attempts as inference changes, each within 0.0015 BPB of its parent. A10 introduced CUDA-graph replay, ``the only lever that can raise speed without a quality cost'' in Opus's words, followed by fused kernels (A14, A22), a ring K/V cache (A18) and a custom attention kernel (A19). Scored decode speed rose from \CROpPreAdapterDecode$\times$ to about 31$\times$ that of the starting model, while end-to-end speed stayed near 5$\times$ (\S\ref{sec:inference}). The final frontier is A23, A24 and A27.

\needspace{8\baselineskip}\textbf{The other agents found the same lever.} On AP-Q's path (Appendix Table~\ref{tab:apqpath}) a batch cut that expected ``roughly four times as many optimizer updates within the fixed training window'' gave the largest validation gain ($-0.108$ BPB). Depth cuts followed, partly because ``the smaller model processes more tokens in the fixed training time'' (A8). In Pair-A, Codex expected ``higher token throughput within Contract T'' to offset a shallower model. In a small fixed-token pilot, the same Codex agent's best model was \CRFivePilotRatioLo--\CRFivePilotRatioHi$\times$ larger than under fixed time in all three launches that changed the architecture, a tendency from single runs, not a measured contract effect (\S\ref{sec:pilot}).

\subsection{Did they find better models? Matched-exposure verification}\label{sec:verify}
\textbf{Why a new test was needed.} The submitted version compared 300\,s discovery runs (seed 0, validation shard) with a 201.3M-token retraining (seeds 3 to 5, held-out shard), so seeds, evaluation data and exposure changed at once. \textbf{E1}, pre-registered on 2026-11-04, varies only the budget. It retrains frozen AP-Q and AR-ref at 88.6M, 157.3M and 201.3M tokens with equal updates and at 300\,s, on fresh seeds 6, 7 and 8 used in every cell, with the same data order and held-out shard (24 runs). A second plan (2026-11-08) retrained Opus's frontier at 201.3M tokens against E1's AR-ref runs, within 3\% of Opus's own 300\,s exposure.

\textbf{Equal time.} At 300\,s AP-Q trains on \CREOneTokRatio$\times$ as many tokens as AR-ref (Figure~\ref{fig:e1}a), and the held-out difference, \CREOneTimeHeldThree{} \CREOneTimeHeldCI, is not resolved, which is not evidence that the two are equal. \textbf{Equal tokens.} AP-Q is worse at every budget, by \CREOneMatchedLoAbs--\CREOneMatchedHiAbs{} held-out BPB, and for each of the three seeds at each budget, while within-recipe seed SDs are at most \CREOneMaxSD{} (Figure~\ref{fig:e1}b, Table~\ref{tab:results}). \needspace{9\baselineskip}
\subsection{Why Opus decodes 31$\times$ faster but generates only 5$\times$ faster}\label{sec:inference}
A language model reads the prompt once (\emph{prefill}), storing attention keys and values in a \emph{K/V cache}, then generates one token per small \emph{decode} step. The score times only the 127 decode steps after a 1{,}024-token prompt. At batch size 1 a small model's decode step is dominated by the CPU launching tiny GPU programs (\emph{kernels}), \CRIAKernBase{} per token for the starting model. A \emph{CUDA graph} records this sequence once and replays it with one call, and \emph{kernel fusion} merges small kernels into larger ones (\CRIAKernEager{} become \CRIAKernFused{} per token).

\begin{figure}[H]
\centering\includegraphics[width=\linewidth]{figures/cr_inference.pdf}
\caption{Pre-registered ablations of A23, A24 and A27 (medians, whiskers: range). (a) One mechanism removed at a time. (b) One generation (1{,}024-token prompt, 128 new tokens) to scale.}\label{fig:inference}
\end{figure}

\textbf{What the ablations show} (Figure~\ref{fig:inference}a, \CRIARuns{} runs). Without graph replay decoding is \CRIAGraphLo--\CRIAGraphHi$\times$ slower and without fusion \CRIAFusionLo--\CRIAFusionHi$\times$ slower (the effects interact), while the smaller model alone decodes \CRIAArchLo--\CRIAArchHi$\times$ faster than the starting model. \textbf{What the score does not time} (Figure~\ref{fig:inference}b). From A10 on, Opus recorded the graph inside prefill for every prompt, noting that ``Prefill time rose from 6.4 ms to 81 ms'' (A11). Prefill grows from \CRThreePreBase{} to \CRThreePreOpus{} ms while decoding shrinks from \CRThreeDecBase{} to \CRThreeDecOpus{} ms, so a generation is \CRThreeEtoEX$\times$, not \CRThreeDecX$\times$, faster. Every variant passed the correctness checks, which compare greedy tokens and logits with a full-prefix reference on 64- and 256-token prefixes and so cover neither the timed window nor the 1{,}024-token ring cache. With one workload on one GPU type, and with graph replay and fusion absent from the starting model and AR-ref, 31$\times$ does not isolate the architecture and need not hold for other workloads.

\subsection{Primary result}
Every agent pulled the speed lever of the 300\,s contract, which did not buy better learning per token: at equal tokens AP-Q is worse by \CREOneMatchedLoAbs--\CREOneMatchedHiAbs{} held-out BPB and Opus by \CRMTDLoAbs--\CRMTDHiAbs. The efficiency is real. AP-Q generates \CRDecodeRatio$\times$ faster with \CRParamReduction\% fewer parameters, and Opus's \CRIATotalMed$\times$ scored decode speed-up is \CRIAEtoEMed$\times$ end to end.

\subsection{Agent and Harness}\label{sec:agent}
% P2-02: written with and approved by the author (2026-11-10).
My role was to design the research framework, define the objectives, compute budgets and evaluation rules, and maintain the experimental infrastructure. The AI agents independently proposed hypotheses, modified Transformer architectures and training settings, and selected which candidates to explore. Every historical AutoPareto and AutoResearch attempt was proposed by \texttt{gpt-5.6-sol} at high reasoning effort, which operated the protected runner on the GPU pod over SSH, through the Codex desktop app or, for five seed-42 attempts, Cursor's agent (Appendix~\ref{app:repro}). In the Pair-A harness (\S\ref{sec:pilot}), Codex CLI 0.153.0 ran \texttt{gpt-5.6-sol} at high reasoning in a fresh container for every call (600-second timeout), seeing five staged files and writing only \texttt{train.py}. The Opus arm ran \texttt{claude-opus-5-5} (effort \texttt{xhigh}) through Claude Code 2.1.318 on the host, with file tools only, no shell, and the same prompts, output schemas and two calls per attempt; it was isolated by CLI permissions, file modes and hash checks, tested by a canary before the campaign. Historical isolation relied on instructions plus hash checks: protected files were hashed before and after every attempt, and any change outside \texttt{train.py} rejected the run. No agent saw downstream results. All agent session logs are retained privately and not publicly released.

\subsection{Tools}
% P2-03: written with and approved by the author (2026-11-10).
All training and measurement ran in BF16 on NVIDIA A40 GPUs (several physical cards across eras); software per era is in Appendix Table~\ref{tab:env}. The panel, E1 and the Opus retraining used Python 3.10.18 with PyTorch 2.9.1+cu128. The Pair-A campaigns ran in a separate Python 3.12 runtime with PyTorch 2.8.0+cu128 (2.9.1 in the September pilot), and the inference ablations also used PyTorch 2.8.0. The discovery-era environment was not logged at run time; the repository's lockfile then pinned PyTorch 2.9.1+cu128. A trusted controller stages each candidate, checks source and parent SHA-256 hashes, runs training, verifies the checkpoint, calls the protected BPB and inference evaluators, and appends the outcome to the registry and lineage.

\subsection{Research Loop}\label{sec:loop}
% P2-04: written with and approved by the author (2026-11-10).
Each attempt follows the loop below (historical campaigns: runner functions \texttt{validate\_autopareto\_proposal} and \texttt{raw\_pareto\_rows}; Pair-A: \texttt{campaign\_controller.py}, \texttt{campaign.py}).
{\small\begin{enumerate}\setlength{\itemsep}{0pt}\setlength{\parskip}{0pt}
\item Stage the campaign view (this campaign's records and current frontier) and the parent source.
\item The agent returns a hypothesis, intended change, change category, parent identifier and a patch to \texttt{train.py}.
\item Validate: the parent must be on the current frontier (historical) or parent-eligible in the same arm (Pair-A); protected-file and source hashes must match; only \texttt{train.py} may change.
\item Train under the contract (300\,s; or $N^\star$ counted tokens in the Pair-A fixed-token arm).
\item Protected evaluation: validation BPB, cached/full-logit correctness, cached-decode throughput, peak allocated memory.
\item Append an immutable record (hypothesis, patch, hashes, metrics, failure text); failures consume the attempt.
\item Update the archive: historically, a completed candidate is retained if neither another completed candidate nor the registered same-seed baseline dominates it on raw BPB, decode and memory (no noise margin); the agent labelled each outcome, and the runner rejected any label that disagreed with this rule.
\item The next attempt chooses its parent among retained (historical) or parent-eligible (Pair-A) records.
\end{enumerate}}
Without noise margins the archive admits noise-level trade-offs: A09 and A10 build the same model, yet A10 was retained. In Pair-A every quality-valid record was parent-eligible even when its speed was uncertain.
\humanauthor[P2-05b]{Figure~\ref{fig:loop} in Part~1 shows this loop and its protected boundary. Because any eligible record can be a parent, every campaign is a tree: Opus's branches are drawn from its recorded parent links in Figure~\ref{fig:opus} and AP-Q's in Appendix Figure~\ref{fig:lineagefull}.}

\subsection{Human Interventions}\label{sec:interventions}
% P2-06: written with and approved by the author (2026-11-12).
I chose the objectives, the 300-second contract, the matched-exposure design, the panel, E1 and Opus-test recipes, the comparators and the interpretation. I made or approved each intervention below; AI coding assistants carried out several at my instruction. \textbf{(i)} \emph{Seed-42 AutoPareto rollback.} Attempt 4 failed the cache-correctness check and was labelled dominated, and attempts 5--8 ran on 2026-07-28. When the check was found faulty and repaired, I discarded attempts 5--8 because they had followed a frontier that wrongly excluded attempt 4 (ids 88--90 are absent); attempt 4 was re-measured on a recreated checkpoint and changed to retained, and attempt 5 was replayed. The AP-Q lineage (seed 0) has no recorded scientific intervention: its program, evaluator and records were not changed. Interventions whose authorship cannot be reconstructed are excluded from claims of autonomous contribution.

Identical token streams across panel recipes were verified at run time, and E1's 24 runs and the Opus retraining's \CRMTRuns{} passed every pre-registered integrity gate on the first attempt.}

\subsection{Reproducibility}\label{sec:reproduce}
\humanauthor[P2-17]{We separate three levels, with commands in Appendix~\ref{app:howto}. \emph{Level 1, artifact reproduction} (no GPU): one script, \texttt{paper/build\_camera\_ready.sh}, regenerates every number, table and figure from the archived records and checks them against the committed audit. It needs the full evidence tree, part of which (database snapshot, campaign histories) awaits the public release, while the pre-registered E1 and Opus analyses already rerun from committed records. \emph{Level 2, recipe reproduction} (one A40): the frozen recipe sources, hashed plans and executors retrain AP-Q, AR-ref and Opus's recipes under the recorded token or time contract. The training-shard revision and one GPU kernel are not pinned in code, so exact losses may differ slightly. \emph{Level 3, agent-campaign reproduction}: the Pair-A controller, prompts, output schemas and permission checks run a comparable campaign with Codex CLI or Claude Code, but proprietary model state means a new campaign will not repeat the same attempts, and pod setup is partly manual. The historical campaigns were operated by hand through desktop agents and have no single entry point.}

\subsection{Significance of result}
\humanauthor[P2-12]{Matched-exposure verification shows that the quality ranking depends on the contract, while the efficiency result survives every contract we tested. The pre-registered token sweep finds no budget at which AP-Q is better per token, so its fixed-time standing reflects its extra exposure, not better learning per token. Agents from two model families found the same lever and wrote it into their hypotheses: under a time budget, a smaller program trains on more data. The second pushed it further, was worse still per token, and took most of its decode gain from graph replay whose recording the metric did not time. A benchmark that ranks agents under a throughput-coupled budget is partly ranking how fast their candidates train. Reported quality gains should be rechecked under controlled exposure and speed gains under end-to-end timing.}

\subsection{Interpretability}
\humanauthor[P2-13]{Every preserved attempt record keeps the agent's hypothesis, intended change, applied patch, parent, source and parent hashes, status, raw metrics and failure text, so a headline number can be traced to a source file, the edit that produced it and the hypothesis recorded before it (Figure~\ref{fig:opus}, Appendix~\ref{app:decisions}). We separate what the agent predicted, what it changed, what the evaluator measured and what our retrospective analysis concludes, and we quote agent motives rather than infer them. Session logs survive for every campaign, privately for the historical ones because they contain infrastructure access details. The record also exposes gaps between intent and execution: AP-Q's recorded intended changes for A7 and A8 predict widths 384, 320 and 256, but width rounding kept A7 at 384 and took A8 straight to 256.}

\subsection{Limitations}
\humanauthor[P2-14]{\emph{Addressed since review:} the confounded reversal (E1 holds seeds and evaluation data fixed and varies only the budget), the single matched horizon (three budgets plus 300\,s) and the fixed-time variability (E1 seeds, session and seed effects above). \emph{Remaining:} one GPU type (A40) and small models, with no scale-transfer, cross-GPU or energy claim. Matched-token verification compares complete recipes, so architecture and optimizer changes stay bundled, and in E1 tokens and updates change together (a batch-varied follow-up was not run). E1 resolves the gap with three seeds but not its slope with tokens, and its exposure--architecture split is exploratory. Selection narrowed after discovery, and a pre-registered full-size candidate (exp 109) was never confirmed. Each Pair-A agent ran one seed, so we do not rank agents. The Codex arm stopped after 22 attempts, and the Opus arm had a longer agent timeout and two extra attempts (neither changes a conclusion, Appendix~\ref{app:faq}). The Opus retraining covers one budget and replaces its time-fraction learning-rate progress with the token fraction. The ablations measure one workload on one host, and graph replay and fusion were not applied to the baseline or AR-ref. The fixed-time versus fixed-token pilot (\S\ref{sec:pilot}) shows a tendency but is too small for a behavioural conclusion. Historical comparators differ in search space, budget, seed and failure history, so they support no search-policy ranking.}

\subsection{Pair-A: controlled agent campaigns}\label{sec:pilot}
\humanauthor[P2-15]{We piloted a prospective test of H2, whether the contract changes what an agent pursues. Two arms whose programs differ only in the contract paragraph started from identical bytes at seed 3. T trains for 300\,s. N trains for $N^\star$ counted tokens, the largest multiple of 524,288 not above the median of three baseline calibration runs: 88,604,672 in the first launches and 85,458,944 after recalibration on a new A40 from 2026-09-09. Five Codex launch lineages ran between 2026-09-05 and 2026-09-17, with protocol changes between them, and Part~\ref{partone} reports the 2026-09-14 restart (22 attempts per arm). In the lineage reported at submission, 2 of the first 4 fixed-time attempts are invalid. When a candidate's training loop ended before the trusted stop, the harness re-executed the training body and checkpointed a freshly initialized model (candidate-reported step 0 against 1,264 observed updates, BPB 3.2159). The controller still marked these runs quality-valid and parent-eligible, and the agent's next hypothesis blamed its learning rates. The Opus harness treats an early normal exit as a candidate failure.}
\humanauthor[P2-15b]{\textbf{What the two arms explored} (Appendix Table~\ref{tab:pilot}). In each of the three launches in which the agent changed the architecture, the fixed-token arm's best model was larger (\CRFivePilotNA M against \CRFivePilotTA M, \CRFivePilotNB M against \CRFivePilotTB M and \CRFivePilotNC M against \CRFivePilotTC M parameters). Only fixed-token attempts grew the model, to 10 and 12 layers, expecting a better BPB ``by increasing model capacity'', while under fixed time the agent cut depth and width and trained on up to 175M tokens. Batch reductions do not separate the arms: both reduced the batch on 6 September, and on 9 and 14 September each did so while the other did not. With a shared seed and starting code, a changing harness and six fixed-time attempts lost to the defect above, this is an observed tendency, not an estimated contract effect.}

\humanauthor[P2-16]{\textbf{What the speed metric does not time.} The Opus arm inherited the Codex arm's frozen contract, schedule, baseline, data, evaluator and Pareto rule. Besides the agent backend, isolation, call timeout and attempt budget (\S\ref{sec:interventions}), only the early-exit repair and a mid-campaign FP32 adjudication fix changed. Its largest decode gains came from recording the decode CUDA graph, and later compiled regions, inside the untimed \texttt{prefill} (\S\ref{sec:inference}), which its program calls ``diagnostic''. This was permitted, so we report both speeds. A scored prefill-inclusive metric and output checks inside timed windows belong in the harness.}

\section{Broader Impact}\label{partthree}
Resource contracts are part of the scientific specification of autonomous research. Neither contract is wrong: a time budget asks which program gives the best model per GPU-second, a token budget which gives the best model per training token, and a paper should say which question its scores answer. When an agent controls architecture and training together, a time allowance changes how much data a faster candidate sees. A token allowance removes that pathway while letting update count and compute vary. The measurement contract matters in the same way: an agent rewarded for a decode-only number will improve the decode-only number, here largely by moving graph recording into the untimed prefill. Agents read a contract the way an optimizer reads a loss: agents from both model families pulled the throughput lever within their first three attempts, and Opus moved work into the untimed prefill while noting its cost. Contract designers should assume that an agent will find every degree of freedom the contract leaves open. The contract may also steer what agents build: in our small pilot the same agent kept larger models under a fixed-token budget than under a fixed-time one. A replicated, seed-paired study could test whether this holds.

\textbf{A contract card.} We propose that autonomous-ML papers report, for every scored result:
{\setlength{\leftmargini}{1.6em}\begin{enumerate}\setlength{\itemsep}{0pt}\setlength{\parskip}{0pt}\setlength{\topsep}{2pt}
\item the stopping rule and the learning-rate progress variable,
\item the seeds used for discovery and for comparison,
\item tokens, optimizer updates and FLOPs per scored run,
\item session-throughput variation under time contracts,
\item what each speed or memory metric times and excludes, such as prefill,
\item the selection funnel from attempts to reported recipes, with dates, and
\item harness invariants such as checkpoint lineage and failure semantics.
\end{enumerate}}
\noindent Our own harness once accepted a checkpoint of an untrained model as quality-valid. Invariant checks belong in the protected boundary, not in post-hoc audits.

\textbf{Future direction: agents that ask for their own confirmation.} Here humans noticed the coupling and ran matched-resource retraining after the search. A natural next step, which we have not built or tested, is to let the agent request it: before claiming a quality gain under a time contract, the agent would ask the harness for a matched-token retraining against its parent on fresh seeds, and an end-to-end timing before claiming a speed gain. Other open follow-ups are a batch-varied test that separates tokens from updates, a matched-token test of exp 109, a seed-paired contract study replicated under one frozen harness with prefill-inclusive speed scoring, and a scaling pilot.

Efficiency may reduce the cost of an individual experiment or deployment, yet cheaper experiments can increase total experimentation. We report no energy benefit because the artifacts contain no campaign-wide energy accounting. Small-model benchmark results do not establish safe or reliable use in consequential settings. Human accountability grows with experiment volume: humans set objectives, repair infrastructure, decide which failures are scientific and interpret evidence, and an auditable record should keep the human question, the agent's prediction, the source edit, the measured outcome and the retrospective explanation distinguishable.
\label{partthreeend}

\section{Glossary}\label{app:glossary}
\humanauthor[P2-01 Glossary]{\textbf{Bits per byte (BPB)}: average bits needed to encode each byte of unseen text under the model. Lower is better. \emph{Validation} BPB is the discovery score; \emph{held-out} BPB uses a separate pinned shard used only for confirmation. The two are never compared with each other.\par
\textbf{Contract}: the rule that stops training; \emph{fixed time} (300\,s of measured training) or \emph{fixed tokens} (a set number of counted training tokens).\par
\textbf{Exposure}: training tokens processed before evaluation. \textbf{Optimizer update}: one change of the weights from one batch of tokens.\par
\textbf{Matched-exposure retraining}: retraining frozen recipes to the same token count (for AP-Q, AR-ref and Opus's recipes also the same updates and batch).\par
\textbf{E1}: the pre-registered token-response experiment (seeds 6--8; 88.6M, 157.3M, 201.3M tokens and 300\,s).\par
\textbf{Campaign / attempt}: one agent's sequence of attempts under one seed. An attempt is one proposal (hypothesis and patch), trained and measured once. Failures count.\par
\textbf{Parent}: the archived attempt whose source an attempt edits. Historical parents had to be retained, Pair-A parents only quality-valid (\emph{parent-eligible}).\par
\textbf{Pareto frontier / retained}: recipes that no other recipe matches or beats on all of BPB, decode speed and memory while beating on one. In Pair-A, speed-uncertain records are not on the frontier but remain parent-eligible.\par
\textbf{Autoregressive decoding, prefill, K/V cache}: generating one token at a time. Prefill processes the prompt once and fills the cache of attention keys and values so that each new token needs one small step.\par
\textbf{Decode-only vs end-to-end speed}: cached single-token steps after an untimed prefill, vs prefill plus generation.\par
\textbf{CUDA graph}: a recorded sequence of GPU kernels replayed with one CPU call. \textbf{Kernel fusion}: merging small GPU kernels into fewer, larger ones.\par
\textbf{Ablation}: removing one component to measure its effect. \textbf{95\% confidence interval (CI)}: a range computed from the data that expresses uncertainty about an effect. A CI spanning zero means the sign is not resolved.\par
\textbf{Recipe names}: AP-Q = A22 = exp 134 (AP292 in the submitted version); AP-F = A25 = exp 137 (AP299); AP-S = A24 = exp 136 (AP294); AR-ref = exp 68; Opus A23, A24, A27 = Pair-A Opus attempts; T and N are the fixed-time and fixed-token arms of Pair-A.}

\section{Related work}\label{app:related}
Operator-level, grammar-based and multi-objective architecture search \citep{primer,einspace,mote,monaq}, multi-fidelity allocation \citep{hyperband,bohb} and agentic research systems \citep{autodiscovery,mlestar,airesearcher,mledojo} are established, as are budget effects on model rankings \citep{dehghani2022efficiency,geiping2023cramming,hoffmann2022chinchilla}. The classical comparators are random search, TPE \citep{bergstra2011tpe}, MOTPE \citep{ozaki2020motpe}, NSGA-II \citep{deb2002nsga2} and CMA-ES \citep{hansen2001cmaes} over a fixed parameter vector, and \citet{ferreira} compare LLM agents with such optimizers on autoresearch. Primer searches compositions of low-level operations and finds stronger operator-level novelty than our numerical edits. Our architectural changes (fewer layers, smaller batches, attention windows) are not novel in themselves. Our contribution is an audit of what a resource contract rewards, with matched-exposure verification. The zero-shot suite is ARC-Easy \citep{clark2018arc}, PIQA \citep{bisk2020piqa}, LAMBADA \citep{paperno2016lambada} and BLiMP \citep{warstadt2020blimp}.

\section{Questions a reader may ask}\label{app:faq}
\textbf{Is AP-Q simply a worse model?} Per training token, yes (Table~\ref{tab:results}). Per GPU-second its difference from AR-ref is not resolved (300\,s, E1) while it is \CRParamReduction\% smaller, decodes \CRDecodeRatio$\times$ faster and uses \CRMemoryReduction\% less inference memory. Which matters depends on whether compute time or data is the scarce resource.

\textbf{Why not use a fixed-token contract from the start?} A fixed-time contract is the autoresearch standard and answers a practical question: the best model from a fixed amount of GPU time. It is not wrong, but it scores a program's throughput and its per-token quality together. A fixed-token contract isolates per-token quality but lets compute and update count vary. We report both.

\textbf{Why did every agent shrink the model?} Under 300\,s, BPB improves with more updates and tokens, and a smaller model gets more of both. The agents' hypotheses say so (Table~\ref{tab:reasoning}). E1 prices the trade for AP-Q: it trains \CREOneRho$\times$ faster but needs about \CREOneK$\times$ AR-ref's tokens for equal quality, so at 300\,s the two roughly cancel. Opus's recipes would need more than \CRMTKBound$\times$ AR-ref's tokens, about their speed advantage, and post hoc, at 201.3M tokens they do not differ resolvably from AR-ref at 300\,s (95\% CIs span zero).

\textbf{Does E1 prove that exposure is the only cause?} No. E1 shows that at equal tokens and updates AP-Q is worse, on the same seeds and data, and its exploratory split attributes the 300\,s result to extra tokens offsetting a weaker architecture. Tokens and updates move together, and architecture and optimizer edits are bundled, so finer causes are not separated.

\textbf{Are three seeds enough?} For the matched-token gap, yes: \CREOneMatchedLoAbs--\CREOneMatchedHiAbs{} held-out BPB against a within-recipe seed SD of at most \CREOneMaxSD, on all \CREOnePairs{} seed--budget pairs, and the panel result replicates on other seeds and another A40. For the slope of the gap with tokens, or to show equivalence at 300\,s, no.

\textbf{Did Opus game the decode metric?} It stayed within the permitted surface: the adapter had to compute the same outputs, and every variant passed the correctness checks with identical greedy tokens on the 64- and 256-token prefixes they cover. Those checks reach neither the timed window nor the 1{,}024-token ring cache, so full-workload equivalence is not established. Its records describe graph replay as a fix for launch-bound decode and note the prefill cost (Table~\ref{tab:reasoning}), so it was the metric's definition, not a rule violation, that rewarded the placement. We report decode-only and end-to-end speed side by side and recommend prefill-inclusive scoring.

\textbf{Is the Codex--Opus comparison fair?} The arms share the baseline, seed, prompt bytes, output schemas, contract and Pareto rule. They differ in agent-call timeout (600 vs 900\,s), isolation and attempt count (\CRCxAttempts{} vs \CROpAttempts), and each ran one seed. At \CRCxAttempts{} attempts each the best validation BPBs are \CRCxBestBPB{} and \CROpBestTwentyTwo. We draw no agent ranking. The arms show the same exposure strategy and supply recipes for retraining.

\textbf{Does the Opus extension to \CROpAttempts{} attempts change anything?} No. Its best validation BPB (\CROpBestFrozen) came within the frozen first 25 attempts. The frozen frontier (\CROpFrontierFrozen) shares A23 and A24 with the retrained set, and the third retrained recipe, A27, matches A23's held-out gap to AR-ref to three decimals (Table~\ref{tab:results}).

\textbf{Could the time-to-token mapping handicap Opus's recipes?} The mapping changed only driver lines (clock, stop, progress). Model and optimizer code stayed byte-identical. The 201.3M tokens and 1{,}536 updates are within 3\% of Opus's own 300\,s runs (\CROpTokLo--\CROpTokHi M tokens, \CROpUpdLo--\CROpUpdHi{} updates), so its recipes were scored at almost the exposure they were tuned for, and an AR-ref drift control reproduced E1 within \CRMTDriftAbs{} BPB.

\textbf{Were the reported recipes cherry-picked?} The funnel and its dates are in Table~\ref{tab:funnel}: the representative rule predates the first attempt, the four-role selector preceded the seeds 0--2 confirmation, and the panel was assembled after it. A full-size candidate (exp 109) was never confirmed. E1, the Opus retraining and the ablations were pre-registered, and the Opus retraining covers its whole frontier.

\textbf{Does this transfer to larger models or other GPUs?} Untested: one GPU type and recipes of 18--50M parameters.
